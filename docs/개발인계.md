# 후속 개발자·개발 에이전트 인계

## 원칙

이 패키지는 실제 실행한 코어 시험과 미실행한 외부 연동을 분리한 RC다. “MCP SDK 설치 성공”, “법제처 실데이터 검증 완료”, “8개 실제 LLM 호출 성공”, “전국 조례 전수 수집”을 시험 없이 적지 않는다. 규칙 모드를 외부 에이전트 8개로 포장하지 않는다.

## 모듈 지도

| 모듈 | 책임 |
|---|---|
| `models.py` | 공개 입력 스키마·내부 문서·조문·변경 작업 |
| `config.py` | 환경설정·외부 HTTP 기본 제한 |
| `client.py` | 고정 공식 API 호출·예산·재시도·캐시·범위 표시 |
| `normalize.py` | JSON/XML·조문/가지조문/항호목·부칙·별표 메타데이터 |
| `analysis.py` | 규칙 점검·비교·시점·인용·버전 차이·영향·절차 |
| `drafting.py` | 입법 대안·제정 골격·원문 조건부 일부개정문 |
| `llm.py` | 선택적 역할별 Gemini 요청·스키마·조문 제안 검증 |
| `audit.py` | 근거 ID·원문 인용 검사·최종 보류표·Markdown |
| `agents.py` | 8역할 실행 순서·공유 근거·팀 검토 결과 전달 |
| `monitor.py` | 성공 스냅샷·최종 기준·원자적 변경 기록 |
| `security.py` | Host/Origin·정적 Bearer·요청량·본문 크기 |

| `cli.py` | 데모·검토보고서·상태 점검·일회 감시 |

## 반드시 유지할 계약

외부 입력이 `source_state=live` 같은 신뢰 상태를 스스로 지정하지 못해야 한다. 직접 가져온 공식 원문과 사용자 입력을 합쳐 “검증 완료”로 만들지 않는다. 검색 실패·총건수 모순·반복 페이지·호출 예산 초과는 0건이나 완전 수집이 아니다.

특정 시행 버전은 `MST+efYd`로 요청하며 `ID`를 함께 보내지 않는다. 공포일 기준은 `law_view=promulgated`로 구분한다. `as_of` 변경만으로 역사 버전을 자동 복원했다고 하지 않는다.

`possible_gap`과 수치·문구 차이는 법적 판단이 아니다. 기준 조례가 없을 때 첫 결과를 사용하거나 제정 필요성을 확정하지 않는다. 기관명 추정 별칭으로 행정구역 개편 사실을 만들어내지 않는다.

모델의 모든 사실·법적 검토 주장은 근거 ID와 원문을 확인한다. 인용 검사는 의미 타당성 검증과 분리한다. A8의 오류도 최종 검사에 다시 포함한다. 초안을 자동으로 공포·의결·외부 저장하는 기능을 추가하지 않는다.

변경 작업에는 기준 해시와 대상 원문이 필요하다. 사용자 확인 없이 원문을 새 버전으로 바꾸거나 전역 단어 치환·조번호 재배치를 하지 않는다. 스냅샷은 실패 시 지우지 않는다.

## 다음 검증 우선순위

1. 승인된 환경에 의존성을 설치하여 실제 MCP STDIO/HTTP 연결과 도구 스키마를 검증한다.
2. 본인 법제처 API로 조례·법률·시행령·시행규칙·다양한 기관의 JSON/XML 응답 표본을 확보한다.
3. 실제 버전·기관·조문 구조와 공식 웹 원문을 대조하고, 오류 표본을 비밀값 없이 회귀시험에 추가한다.
4. 동의한 공개 자료로 Gemini 구조화 응답·입력 범위·모델 한도와 역할 간 의견 전달을 실검증한다.
5. 조례 제정/개정 경험이 있는 담당자와 기준 사례를 만들어 오탐·미탐·시간 절감 효과를 측정한다.

## 확장 후보 — 현재 구현 완료와 구분

별표·별지 파일의 안전한 다운로드와 표 구조 검증, PDF/HWPX 파서, 판례·법제처 의견제시와의 연동, 법령-조례-규칙-지침 간접 영향 그래프, 기관 코드·정식 명칭 마스터, 사용자별 OAuth·권한·비용 예산, 공식 법령 변경 피드 보완, 전자결재용 문서 내보내기 등을 별도 과업으로 검토할 수 있다.

소스·문서 라이선스와 공공데이터 이용조건을 먼저 확인하고 외부 저장소의 코드를 무단 복사하지 않는다. 현재 비교표에는 도입 기능과 참고만 한 기능을 구별해 적었다.
