# 보안·자료처리·운영 경계

## 구현한 경계

고정된 법제처 API 주소만 조회하며, 사용자가 임의 URL을 서버에 가져오게 하지 않는다. 리다이렉트를 따라 인증정보를 다른 호스트로 보내지 않는다. 인증값은 환경변수에서만 읽고 오류 메시지·상태 도구에 출력하지 않는다. 서버 토큰을 법제처 인증값으로 전달하지 않는다.

HTTP에서 Host/Origin을 확인하고 외부 공개 배포에는 토큰 또는 명시적인 공개 읽기 모드가 필요하다. URL 인증 파라미터를 거부한다. 기본 요청 본문은 180만 바이트, 프로세스당 요청량은 분당 60개로 제한한다. 외부 배포 서버에는 동시 연결 한도도 둔다. 이는 분산 서비스 전체의 사용자별 할당량·보안 게이트웨이를 대체하지 않는다.

법제처 호출은 기본 요청당 36회, 설정상 최대 80회 범위이며 일부 일시 오류만 제한적으로 재시도한다. HTTP 응답은 600만 바이트로 제한하고 XML 외부 엔티티를 허용하지 않는다. 공개 법령 응답만 메모리에 캐시하고 인증값의 해시로 캐시 영역을 구분한다. 요청 간 사용자 제공 검토 문서의 캐시는 만들지 않는다.

## 데이터가 가는 곳

| 데이터 | 본 패키지의 기본 처리 |
|---|---|
| 법제처 API 인증값 | 서버 환경변수. 공식 API 호출에만 사용 |
| MCP 접속 토큰 | HTTP 경계 인증에만 사용 |
| 공식 법령 원문 | 메모리 캐시. CLI 감시 사용 시 지정 SQLite에 저장 |
| 사용자 제공 문서 | 요청 메모리에서 처리. 서버가 별도 DB에 저장하지 않음 |
| CLI 입력·출력 | 사용자가 지정한 로컬 파일로 저장 가능 |
| Gemini 입력 | 서버 설정과 요청 동의가 모두 있는 경우 외부 전송 |
| MCP 도구 결과 | 연결한 MCP 호스트에 전달됨 |

서버가 저장하지 않는다고 해서 호스트 AI 서비스·프록시·운영 플랫폼이 보관하지 않는다는 뜻은 아니다. 그 서비스의 대화·도구 결과·로그 정책을 별도로 확인해야 한다.

## 모델 관련 경계

문서 안의 지시는 자료로 취급하고 도구·셸·외부 URL 실행 명령으로 수행하지 않는다. Gemini 응답은 JSON 스키마로 검증하고, 등록되지 않은 근거와 일치하지 않는 인용문은 채택하지 않는다. 지시문 삽입을 완벽하게 무력화하거나 모델의 법률 해석을 증명하는 장치는 아니다.

주민등록번호·휴대전화·이메일·일부 키 형태의 단순 패턴이 발견되면 외부 모델 요청을 차단한다. 이름·주소·사건 문맥 등 모든 개인정보를 탐지하지 못하므로 비식별화 또는 기관 승인 절차를 대신하지 못한다.

역할별 호출은 최대 8회다. 원문이 입력 한도를 넘으면 제외된 근거 ID와 잘린 분석 내용을 표시한다. 모델 오류·한도·잘못된 JSON이 발생하면 실패로 표시하고, 몰래 다른 모델로 바꾸거나 유료 요청을 반복하지 않는다.

## 법적 판단 관련 경계

“규칙 단서 탐지 → 확인 필요”, “인용문 일치 → 그 문장이 원문에 있음”, “조문 존재 → 지정 버전에 해당 조문이 있음”까지만 주장한다. 그 이후인 사업의 적법성, 재위임 허용성, 개정 의무, 시행기한, 수급자 자격 등은 실제 법령·부칙과 전문 검토가 필요하다.

모든 최종 보고서에 `legal_approval=false`, `submission_ready=false`를 유지한다. 이 값은 기능 고장이 아니라 담당자 승인 없이 법적 확정·공포·제출을 하지 않는 경계다.

## 운영 전 별도 준비사항

공개 인터넷에 노출하기 전 기관 보안성 검토, 접근 권한·로그 보관·키 교체·취약점 점검·의존성 관리·장애 대응·백업을 수행한다. 본 과업에서 외부 침투시험, 패키지 전수 취약점 스캔, 완전한 OAuth 구축, 기관 보안 승인을 수행한 것은 아니다.

일반 공개 모드는 공식자료 검색·조회·비교 등 읽기 도구만 제공한다. 사용자 문서·종합 검토·개정안 작성 도구는 등록하지 않는다. 그래도 공공 API 인증값의 과도한 사용 위험이 있으므로 무인증 운영을 실서비스의 기본 방식으로 선택하지 않는다.
