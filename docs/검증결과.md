# 검증 결과

대상: 조례검토·입법지원 MCP v2.0.0-rc.1 / 검증 기준일: 2026년 9월 22일

## 1. 실제 실행 결과

**자동시험 121개 통과, MCP SDK 통합시험 모듈 1개 건너뜀.** 이 결과는 이 패키지의 핵심 로직·모의응답 시험이며 전국 실제 조례의 적법성 검증률이 아니다.

| 시험 파일 | 범위 | 통과 수 |
|---|---|---:|
| `test_analysis.py` | 비교·시점·인용·개정안 | 26 |
| `test_client.py` | 공식 API 클라이언트·오류·범위 | 20 |
| `test_normalize.py` | 공식 응답·조문 정규화 | 40 |
| `test_pipeline_security_monitor.py` | 8역할·모의 모델·보안·변경 관측 | 35 |
| 합계 | SDK 미실행 범위 제외 | **121** |

`tests/test_sdk_integration.py`는 실제 MCP SDK가 설치되어 있지 않아 모듈 단위로 건너뛰었다. 이 모듈에는 도구 16개 등록, 리소스·호출, Streamable HTTP 앱 생성, 공개 프로필의 민감 도구 제외에 관한 **4개 시험 함수**가 있다. 모의 SDK를 넣어 실제 연결 성공처럼 처리하지 않았다.

최종 pytest 출력은 `docs/qa/pytest-log.txt`, 개별 결과는 `docs/qa/test-results.xml`에 동봉했다. 최종 실행 로그는 `121 passed, 1 skipped in 0.68s`다. 이 시간은 오프라인 단위시험 실행 시간이며 실제 법령 조회·AI 검토 소요시간이 아니다.

| 별도 확인 항목 | 실제 결과 |
|---|---|
| Python 구문 컴파일 | `compileall` 성공 |
| 인증키 없는 CLI 데모 | Markdown·JSON 보고서 생성 성공 |
| 8역할 실행 | A1~A8 모두 completed |
| 데모 공식 API 호출 | 0회 — 실제 원문 조회를 시험한 것이 아님 |
| 데모 LLM 호출 | 0회 — 기본 규칙 모드 |
| 별도 모의 Gemini 시험 | 역할별 호출·인용 오류·조문 제안·동의 조건 시험 포함 |
| MCP SDK 실제 실행 | 미실행 |
| 공식 API 실제 조회 | 이 패키지에서는 미실행 |
| Gemini 실제 생성 | 미실행 |
| GitHub CI / Render 배포 | 설정 파일만 작성. 실행하지 않음 |
| 정기 감시·알림 설치 | 실행 명령 예제만 제공. 설치하지 않음 |

## 2. 실행 환경

Python 3.13.5, Linux. 확인된 패키지는 httpx 0.28.1, pydantic 2.13.4, defusedxml 0.7.1, uvicorn 0.48.0이다. MCP SDK는 미설치이며 공식 API·Gemini 인증값 없이 시험했다. 키 자체는 기록하지 않았다. `docs/qa/environment.json`에 설정 여부만 남겼다.

Python 3.11·3.12용 CI 설정은 작성했지만 이 제작 환경에서 해당 두 버전으로 실행한 것은 아니다. 의존성은 호환 범위로 지정했으며 설치된 전체 패키지를 잠근 공급망 검증 완료 환경은 아니다.

## 3. 어떤 실패 상황을 시험했는가?

**수집과 원문:** 단일 객체 응답, JSON/XML, 한글 인코딩, 장·절 제외, 항·호·목 보존, 가지조문, 부칙·별표 메타데이터, 중복 조번호, HTTP 200 오류 본문, XML 외부 엔터티, 비정상 대용량 응답, 리다이렉트 차단을 확인했다.

**대상과 범위:** 다른 기관·다른 제명·다른 ID/MST의 혼입, 검색 결과 반복, 전체 건수와 페이지 불일치, 한도 도달, 실패와 0건 구별, 명시적 키 설정과 재시도 한도를 확인했다.

**분석과 입안:** 조문 본문·기능·수치·의무 표현, 비교 연산 상한, 시행예정·과거 기준일, 조문·부칙 변경, 직접 인용 영향, 없는 인용 조문, 존재하지만 법적 취지 미확정 상태, 원문 해시 불일치, 기대 원문 불일치, 신설·대체·삭제 충돌 등을 확인했다.

**협업과 모델:** 8역할 실행, 8회의 별도 모의 모델 요청, A7 조문 제안의 형식과 인용 검사, 허위 근거·불일치 인용 제외, 개인정보 단서, 원문 속 지시를 데이터로 취급, A8 자체 오류를 최종 검토표에 반영하는지를 확인했다.

**HTTP와 관측 이력:** Bearer·Host·Origin, URL 인증값 거부, 본문·요청량 제한, 불안전한 공개 설정 거부, SQLite 재시작·변경·미변경, 시행일/공포일 관점 분리, 수집 실패 시 마지막 성공본 보존을 확인했다. ASGI 경계 시험과 실제 MCP 프로토콜 시험은 다르다.

## 4. 가상 데모 해석

예제는 가상 돌봄사업과 가상 조례 2건·가상 상위법 1건이다. 공식 법령 원문이 아니라 `user_provided`로 표시된다. 비교 결과에는 기능 차이 후보가 나타나며, 상위법 구·신 버전이 없으므로 개정영향을 완료하지 못했다고 표시한다. 최종 법적 승인과 제출 준비 상태는 false다.

이 데모의 역할은 결과 구조와 안전한 미확정 표시를 보여주는 것이다. 실제 광주 서구 조례에 특정 조문이 없다는 근거로 사용할 수 없다.

## 5. 운영 전 수용시험

| 단계 | 사용자 환경에서 확인할 사항 | 통과 조건 |
|---|---|---|
| 설치 | `requirements.txt`와 개발 시험 의존성 설치 | 설치 오류와 의존성 충돌 없음 |
| SDK | `pytest` 및 `scripts/smoke_mcp.py` | SDK 시험이 건너뛰지 않고 도구 등록·연결 성공 |
| 공식 원문 | `scripts/live_check.py`, 실제 기준 조례 1건·비교 조례 2건 | 공식 사이트의 제명·기관·버전·조문과 대조 일치 |
| 누락 경계 | 별표·부칙·삭제·가지조문을 포함한 실제 자료 | 누락은 경고로 나타나며 검토 완료로 가장하지 않음 |
| 개정 영향 | 실제 같은 상위법의 구·신 2버전 | 변경 조문·시행일·부칙과 담당자가 대조 |
| 입안 | 실제 개정이력 1건으로 신구대비 재작성 | 잘못된 해시·원문은 차단, 개정 문구는 법무 담당 확인 |
| 외부 모델 | 승인된 공개자료·모델로 선택 실행 | 전송 동의·호출 한도·인용·실제 품질 확인 |
| 감시 | 영속 저장경로·수집 실패·재시작 시험 | 직전 성공본 유지와 변경 기록 정상 |
| 운영 승인 | 기관의 보안·개인정보·법무 검토 | 승인 범위와 담당자 책임을 명확히 기록 |

## 6. 판정

핵심 구현과 오프라인 회귀시험을 갖춘 **배포 후보판**이다. 실제 서비스 연결·원문 충실도·현업 수용시험을 완료한 정식 운영판으로 단정할 수 없다. 모든 법적 오류·간접 영향·개인정보를 검출하거나 모든 조례의 적법성을 보증하지 않는다.
