# 공식 출처와 벤치마크 반영표

확인 기준: 2026년 9월 22일. 아래는 구현 계약과 설계 원칙을 확인하기 위해 열람한 공식 문서·프로젝트의 1차 자료다. 외부 제품을 본 패키지에 모두 통합했다거나, 해당 제품의 성능을 직접 비교 시험했다는 뜻은 아니다. 법령 API 문서는 실호출 시험을 대신하지 않는다.

## 2. 국내외 도구에서 반영한 장점

| ID·사례 | 공개 문서에서 확인한 접근 | 본 개선판에서 반영한 부분 | 반영하지 않은 부분 |
|---|---|---|---|
| S13 [Korean Law MCP](https://github.com/chrisryugj/korean-law-mcp) | 법령·판례·조례 조회, 인용 검증, 시점·개정 영향 조회, 자료 부재와 장애의 구분 | 근거 ID, 원문 인용 대조, 변경 전후 비교, 불완전 수집 표시, 호출 예산 | 해당 서버 코드·판례 Citator·모든 전문 분야 API의 통합·실행은 아님 |
| S14 [legalize CLI·MCP](https://github.com/legalize-kr/cli-tools) | 사람과 에이전트가 함께 쓰는 구조화된 법령·판례·자치법규 조회 도구 | 핵심 로직을 CLI와 MCP에서 공유, 명시적 입력 모델·JSON 결과 | 외부 서비스 계정이나 저장소를 묶어 배포하지 않음 |
| S15 [OpenFisca](https://openfisca.org/en/) | 정책·법규 규칙을 코드로 표현하고 시점별 계산·시험을 수행 | 날짜·버전이 명시된 규칙, 변경 시험, 계산 가능한 판단과 확인 필요 판단의 분리 | OpenFisca 엔진, 세금·급여·지원금 계산모형, 검증된 재정 시뮬레이션은 없음 |
| S16 [docassemble](https://docassemble.org/) | 질문과 조건을 통해 정보를 모으고 문서를 조립하는 방식 | 사업 설명의 구조화, 미확인 질문, 조건별 조문 골격, 신구대비 출력 | docassemble 엔진이나 그 PDF·DOCX 출력 기능을 내장하지 않음 |
| S17 [OASIS LegalDocML / Akoma Ntoso](https://www.oasis-open.org/committees/tc_home.php?wg_abbrev=legaldocml) | 법률 문서의 구조·참조·식별을 명시하는 표준화 접근 | 본칙·부칙·조문키·버전·참조를 분리한 내부 문서 모델 | Akoma Ntoso XML 입출력, 표준 준수 인증은 구현하지 않음 |
| S18 [MCP Python SDK](https://github.com/modelcontextprotocol/python-sdk) | 도구·리소스·프롬프트와 표준 전송 방식, 버전 이행 안내 | 명시적인 도구 설명·입력 스키마, STDIO/Streamable HTTP 구조 | 실제 SDK 프로토콜 연결은 이 제작 환경에서 미시험 |
| S19 [MCP 전송 보안 안내](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) | HTTP Origin 검증, 로컬 바인딩, 인증 등 전송 경계 | Host/Origin 제한, localhost 기본값, Bearer 인증 경계 | OAuth 2.1·기관 SSO·사용자별 권한·분산 요청량 제어는 없음 |
| S20 [Gemini Structured Outputs](https://ai.google.dev/gemini-api/docs/structured-output) | JSON Schema에 따른 모델 결과 구조화 | 역할별 JSON 모델, 근거 필드, 형식 검사와 원문 인용 검사 분리 | JSON 형식 준수를 법률적 정확성 보증으로 취급하지 않음 |
| S21 [Gemini GenerateContent API](https://ai.google.dev/api/generate-content) | 모델 호출 경로·인증 헤더·생성 설정 | 고정된 API 경로, 역할별 호출 상한, 출력 한도, 선택 동의 | 실제 생성·요금·모델별 스키마 지원은 사용자 계정에서 확인 필요 |

## 3. SDK 버전 선택

S18 확인 시점에 공식 SDK의 현행 안정 계열은 v2이며, v1.x는 중요 오류·보안 수정이 유지되는 별도 계열로 안내된다. 원본의 FastMCP 기반을 유지하면서 의도치 않은 주요 버전 변경을 막기 위해 이 패키지는 `mcp>=1.28,<2`를 사용한다. “최신 v2로 이관 완료”라고 표현하지 않는다. 설치 후 `tests/test_sdk_integration.py`와 `scripts/smoke_mcp.py`를 반드시 실행한다.

## 4. 활용·재배포 경계

이 문서는 기능과 설계 원칙을 요약한 것이다. 외부 프로젝트 소스·공식 길라잡이 책자·별표 원문을 복제해 동봉하지 않았다. 관련 엔진을 의존성으로 추가한 것처럼 표시하지 않는다. 후속 개발에서 외부 소스·문서·데이터를 직접 복제하거나 배포할 때는 각각의 라이선스와 이용 조건을 따로 확인해야 한다.

이번 벤치마크는 **서비스 설계·공식 API 계약 비교**다. 전국 지자체의 실제 조례를 대량 수집해 정책성과를 비교한 연구 보고서가 아니다. 실제 조례 비교는 운영 시 확보한 문서와 확인된 범위에서 실행한다.
