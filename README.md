## 가장 먼저 실행하기: 인증키 없는 가상 데모

Python 3.11 이상을 사용합니다. 아래는 **프로젝트 폴더에서** 실행합니다. 기관이 승인한 보안 패치 적용 버전을 선택하세요.

```bash
python -m pip install -r requirements-core.txt
python -m jachi.cli doctor
python -m jachi.cli demo --out output/demo_report
```

`output/demo_report.md`, `output/demo_report.json`이 생성됩니다. 예제의 가상도·가상시·가상 법령은 **시험용 창작 자료**입니다. 실제 정책이나 조례를 검증한 보고서가 아닙니다.

## MCP 서버 실행

```bash
python -m pip install -r requirements.txt
python jachibeopgyu_mcp.py
```

기본은 STDIO입니다. API를 조회하려면 `LAW_OC`를 환경변수로 넣어야 합니다. `.env.example`은 설명용이며 **자동으로 읽지 않습니다**. PowerShell 예시는 다음과 같습니다.

```powershell
$env:LAW_OC = "본인이_발급하거나_설정한_API인증값"
python scripts/live_check.py
python scripts/smoke_mcp.py
```

MCP 클라이언트 등록 형식은 `examples/mcp-stdio.template.json`에 있습니다. Python과 서버 파일 경로는 실제 절대경로로 바꾸세요. 외부 HTTP는 `docs/배포와교체.md`를 먼저 읽고 설정합니다.

## 8개 역할은 어떻게 협업하나요?

```text
A1 사업·입법기획
    ↓
A2 공식자료·버전관리
    ↓
A3 상위법·권한 ─ A4 지자체 비교 ─ A5 개정영향 ─ A6 재정·절차
    └─────────────────────┬────────────────────────┘
                          ↓
                    A7 입안·개정안작성
                          ↓
                    A8 반대검토·근거감사
                          ↓
                    담당자 최종 검토
```

기본 `rules`는 **8개의 역할별 규칙·분석 함수를 실행**합니다. 8개 외부 AI를 호출한 것처럼 표시하지 않습니다. MCP에 연결한 호스트 AI가 결과를 읽어 설명을 작성할 수 있습니다.

`gemini`를 선택하면 서버가 역할당 최대 1회, 총 최대 8회 생성 요청을 추가합니다. A7·A8에는 앞선 역할의 검토사항과 근거 검사 결과, 반대 의견을 넘깁니다. **동일 모델의 역할 분담은 독립된 법률전문가 8명의 심사와 다릅니다.**

## 실제 사업을 검토하는 순서

먼저 `jachi_search_ordinances`로 정식 제명·기관·ID를 확인합니다. `jachi_search_laws`로 관련 상위법을 확인한 뒤 `jachi_review_project`에 기준 조례·비교 조례·상위법 식별자를 전달합니다. `jachi_workflow_guide`에서 전체 입력 스키마를 받을 수 있습니다.

```json
{
  "params": {
    "project": "공개 가능한 사업 목적·대상·지원방식·현재의 문제를 작성",
    "jurisdiction": "공식 API에 등재된 정식 기관명",
    "topic": "조례 주제 또는 정식 제명",
    "search_terms": ["주제어", "관련 용어"],
    "mode": "review",
    "auto_search": true,
    "reasoning": "rules",
    "baseline": null,
    "comparisons": [],
    "parents": []
  }
}
```

식별자가 없으면 검색 후보를 돌려주거나 검토 미확정으로 표시합니다. 자동 기준 선택은 정식 제명·기관의 단일 정확 일치에 한정합니다. 비교 대상 자동 수집은 **검색에서 관측한 서로 다른 기관 최대 4곳의 탐색 표본**이며, 우수 조례 순위나 전국 전수조사가 아닙니다.

기관명을 짧게 `서구`, `광주시`로 입력해서 다른 기관과 섞지 않습니다. API에서 실제 기관명을 확인하여 정확히 입력하세요. 제정·통합·개편 명칭을 임의로 만들어 연결하지 않습니다.

## 상위법 변경을 확인하는 두 가지 방식

**건별 비교:** `jachi_diff_versions` 또는 `jachi_amendment_impact`에 구·신 `DocumentRef`를 지정합니다. 시행일 기준 특정 버전은 `kind=law`, `mst`, `effective_date`가 필요합니다. `law_view=promulgated`는 공포일 기준이며 시행법과 구별합니다.

**반복 점검용 일회 실행:**

```bash
python -m jachi.cli watch --config examples/watchlist.template.json --db data/snapshots.sqlite --out output/watch_result.json
```

첫 실행은 기준본을 저장합니다. 이후의 성공 조회본과 비교하며, 실패하면 기존 기준본을 지우거나 바꾸지 않습니다. `law_view=effective`와 `law_view=promulgated`는 별개의 감시 대상으로 저장합니다. 공포일 기준에서도 모든 과거 개정과 중간 버전을 빠짐없이 수집했다는 뜻은 아닙니다.

이 명령은 **1회 실행 후 종료**합니다. 실제 정기 실행은 운영자가 cron 또는 작업 스케줄러에 등록해야 하며, 이메일·메신저 알림 연계도 별도입니다. 자동 스케줄러를 설치하거나 사용자의 기존 알림을 변경하지 않습니다.

## Gemini 선택 설정

```text
ALLOW_EXTERNAL_LLM=true
GEMINI_API_KEY=본인_비밀키
GEMINI_MODEL=본인_계정에서_사용가능한_모델_ID
```

요청에도 `reasoning="gemini"`, `allow_external_llm=true`가 필요합니다. 모델명·가격·무료 이용량을 코드가 임의로 보장하지 않습니다. 코드에 키를 넣거나 공개 저장소에 업로드하지 마세요.

문서·사업 설명을 외부 모델로 전송하는 방식입니다. 개인정보·비공개 자료는 입력하지 말고 기관의 보안·개인정보 정책에 따라 사용하세요. 단순 패턴 탐지는 완전한 비식별화가 아닙니다. 서버의 Gemini가 꺼져 있어도 **MCP 호스트 서비스가 대화와 도구 결과를 처리하는 것은 별개**입니다.

## 중요한 한계

조문 존재·인용문 일치는 법적 취지와 위임의 적합성을 증명하지 않습니다. 시점·조문별 시행일·부칙·별표·시행규칙·다른 조례와의 관계를 사람이 확인해야 합니다. API 별표 제공 범위는 제한되어 있고 첨부파일 본문 자동 수집은 구현하지 않았습니다.

기본 비교는 문자와 기능 단서 기반입니다. 법적 동등성 판정, 판례 변경 여부 검증, 모든 간접 영향 탐지는 아닙니다. 입법예고·비용추계·사회보장 협의·각종 영향평가 등은 대상 여부를 확인하는 목록이며 모든 사업에 무조건 적용한다고 판정하지 않습니다.

현재 파일 입력은 구조화된 텍스트/JSON입니다. PDF·HWP·HWPX 직접 업로드 파서, 모든 기관 홈페이지 크롤러, 전자결재·의회 자동 제출·공포 기능은 포함되지 않습니다.
